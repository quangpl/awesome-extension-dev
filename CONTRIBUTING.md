# Contributing to Awesome Browser Extension Development

Thank you for helping make this list better! Please read these guidelines before submitting a pull request.

## What belongs here

- Tools, frameworks, libraries, and learning resources **directly useful for building browser extensions**
- Only include projects that are **actively maintained** (last commit within 18 months, or clearly stable/finished)
- Only include projects you have personally used, audited, or have strong evidence of quality
- Open-source projects and reputable commercial services are both welcome

## What does NOT belong here

- Generic web development tools with no extension-specific value
- Abandoned or unmaintained projects (archived repos without a stated reason)
- Blog posts older than 3 years unless they cover a timeless concept
- Self-promotional entries without genuine community adoption

## Entry format

```
- [Name](https://canonical-url) - One concise sentence ending with a period.
```

Rules for entries:

- Use the **canonical URL**: the official project site or GitHub repo (not a blog post about it)
- Description must be **one sentence**, ending with a period
- Be **specific and value-focused**: "Vite plugin that adds HMR for content scripts." beats "A great tool for extension dev."
- No em dashes. Use commas, colons, or parentheses instead.
- Keep alphabetical or importance order within a section

## Adding a new section

Open an issue first if you believe a new top-level section is warranted. Minor additions (a new entry in an existing section) can go straight to a PR.

## Pull request checklist

- [ ] Entry follows the format above
- [ ] URL is the canonical source (verified working)
- [ ] Description is one sentence, ends with a period, contains no em dash
- [ ] Entry is placed in the correct section and in order
- [ ] PR title: `Add [Name] to [Section]`

## Removing or updating entries

If a project is abandoned, the URL is dead, or a better alternative exists, open a PR with your reasoning. Include evidence (e.g., GitHub last-commit date, archived status).

## Code of Conduct

Be respectful. This is a technical resource; keep discussion focused on quality and accuracy.
